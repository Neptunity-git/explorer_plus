# 0029: ホームを「最近使った項目・MOD・ログ」にし、本体と MOD ごとのログを残す

- 日付: 2026-10-15
- 状態: 採用中（ADR 0014 判断2 のホームの中身を置き換える）

## 判断1: ホームは3つの欄だけにする

発案者の判断（「最近使ったファイルと MOD 管理、ログ監視ができるのが良い。それ以外の今の要素はいらない」）。

- 最近使った項目：押すと開く（フォルダは Win11 風ビューでこのタブに開く）
- MOD：入れる・外す・作る・zip にする、MOD ごとの「設定」（発案者の判断：置く）と「ログ」
- ログ：explorer_plus 本体と、MOD ごとに切り替えて見る。新しいものが流れてくる。重さで絞る・コピー・消す
- 取り除いたもの：ビューの選び方（フォルダはタブの ▸ で変える）、クイックアクセス（左の欄にある）

## 判断2: ログは、本体（app）と MOD ごとに分け、ファイルにも残す

発案者の判断（「explorer_plus 自体のログ、別枠で MOD ごとのログ」）。

- 本体のログ：起動、ファイルを変える操作・開く・MOD の出し入れと、その失敗、本体の画面のエラー
- MOD ごとのログ：console.log などとエラー（ランタイムが自動で送る）、その MOD が本体に頼んだことと、断られた理由
- 秘密の値は書かない。通信の URL は ? より後を書かない（API キーなどが入っていることがあるため）
- アプリのデータの logs フォルダに、1行1件で残す（起動し直しても見られる。1MB で古いものへ入れ替え）
- MOD が出しすぎてもアプリが重くならないよう、10 秒に 100 件まで
- ログを読めるのは標準のビュー（ホーム）だけ（ほかの MOD のログを MOD が読めないように）

**検討した選択肢**：
- 開発者ツールのコンソールだけ（却下：MOD を使う人には見つけにくく、起動し直すと消える）
- 画面の中だけで覚える（却下：困ったことが起きたあとで、起動し直すと見られない）

**後で見直す条件**：ログが大きくなりすぎる・探しにくいと感じたとき（検索・日付で絞るなど）。
