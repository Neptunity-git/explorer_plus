# 0011: Win11 風以外の標準ビューは TUI 風にし、軽く動かす

- 日付: 2026-10-14
- 状態: 採用中

## 判断1: 標準ビューの見た目は、Win11 風ビューを除いて TUI 風にする

**決めたこと**：タグビュー・時間割ビュー・樹形図ビューなど、Win11 風ビュー以外の標準ビューは、TUI（ターミナルの中で動くアプリ）のような見た目にする。
等幅の文字、罫線、色の反転での選択、キーボード中心の操作（画面の下にキーの案内）。3D のビュー（ボクセルなど）はこの決まりの外で、別に考える。

**検討した選択肢**：

- 案A（採用）：TUI 風
- 案B（却下）：すべて Win11 風にそろえる。Win11 風は「いつものエクスプローラ」としての入口には良いが、表やまとまりを見せるビューでは
  飾りが多く、描くものが増えて重くなる
- 案C（却下）：ビューごとに自由な見た目。標準ビューの間で操作の覚え方がばらばらになる

**選んだ理由**：発案者の希望。見た目が簡素なぶん軽く動き、キーボードだけで素早く操作できる。「ワクワク」の柱（ADR 0001）とも合う、独自の味になる。

**後で見直す条件**：TUI 風が読みにくいという声が出たとき（文字の大きさ・色の濃さを設定できるようにする）。

## 判断2: 軽さのための決まり

**決めたこと**：TUI 風の標準ビューは、フレームワーク（React など）を使わず素の JavaScript で書く。長い一覧は、見えている行だけを描く。
アニメーションは最小限にする（ADR 0003 の起動アニメーションなど、本体が出すものは別）。

**検討した選択肢**：

- 案A（採用）：素の JavaScript、見えている行だけを描く
- 案B（却下）：フレームワークを使う。読み込みが重くなり、ビューを開くたびに時間がかかる

**選んだ理由**：ビューは iframe ごとに読み込まれるので、1つ1つが軽いことが、タブとビューを増やしても速いことにつながる。

**後で見直す条件**：特になし。

## 判断3: TUI 風の見た目の部品（CSS）を本体が配る

**決めたこと**：本体が `http://mod.localhost/__runtime/tui.css` を配る。MOD は `<link>` で読み込むだけで、標準ビューと同じ TUI 風の見た目
（文字・色・罫線・選択・キーの案内）になる。使うかどうかは MOD の自由。

**検討した選択肢**：

- 案A（採用）：本体が配る
- 案B（却下）：標準ビューごとに CSS を持つ。標準ビューの間で見た目が少しずつずれ、MOD 作者は真似しにくい

**選んだ理由**：MOD 作者が少ない手間で標準ビューと同じ見た目にできる（ADR 0007「MOD 開発者が喜ぶ」）。

**後で見直す条件**：特になし。

## 用語メモ

- TUI（Text User Interface）：文字と罫線だけで作る画面。ターミナルの中で動くアプリ（vim、htop など）の見た目
- 等幅の文字：どの文字も同じ幅のフォント。表や罫線がそろう
- フレームワーク：画面を作るための大きな部品集（React など）。便利だが、読み込みが重くなる
