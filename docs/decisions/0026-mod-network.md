# 0026: MOD の API を広げる（4）通信は、manifest に宛先を書き、入れるときに見せる

- 日付: 2026-10-15
- 状態: 採用中（ADR 0007 の「MOD はネット通信できない」を、条件付きで緩める）

## 判断: 通信先を manifest の network に書き、入れるときの確かめの画面で見せる。スクリプトは読み込ませない

発案者の判断（ADR 0023 判断2：「今回入れる」）。

- 書けるのは https の origin だけ（10 個まで）。パス・IP アドレス・PC や家の中の名前（localhost・.local など）は不可
- MOD の画面の CSP に、その宛先を足す：データ（fetch）・画像・音や動画・フォント・スタイルシート。**script-src には足さない**（MOD のコードは MOD のフォルダの中だけ。入れたあとでコードが変わらないように）
- CSP は Rust が作るので、宛先の検査は TypeScript と Rust の両方で行う（Rust の検査を通らないものは CSP に入れない）
- 入れるときの確かめの画面に宛先を出す。ファイルの中身を読める MOD（fileContent・search）なら「ファイルの中身が外へ送られることがある」と強く注意する。
  更新で宛先が増えたら「新しく増えた」と出す。ホームの MOD の一覧に「通信あり」

**検討した選択肢**：

- 宛先を書いて入れるときに許可（採用）
- ずっと禁止（却下：地図・天気・辞書などのビューが作れない）
- 本体が代わりに通信する API（却下：MOD 作者にとって使い慣れた fetch・img が使えず、作るのが大変）

**分かっていること**：MOD の画面は隔離されているので、通信に Origin（null）・Referer が付かない。これを求めるサービス（OpenStreetMap の公式のタイルなど）は使えないことがある。

**後で見直す条件**：Referer が要るサービスを使いたい MOD が増えたとき（本体が代わりに取ってくる口を検討する）。
