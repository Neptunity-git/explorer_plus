# 0039: MOD がマウスのポインターをロックできるようにする（宣言した MOD にだけ許す）

- 日付: 2026-10-24
- 状態: 採用中（ADR 0007 判断6・ADR 0002 判断4 に追加）

**困りごと**：ポインターロック（マウスのポインターを画面に固定して消し、動いた量 `movementX/Y` だけを受け取る、ブラウザ標準の機能）が、MOD から使えない。
MOD は `sandbox="allow-scripts"` の iframe で動いていて、隔離された iframe ではポインターロックが断られるため。
一人称で歩き回る 3D ビューや、画面の端で止まらないカメラ回転・つまみは、これが無いと作れない。
ADR 0001 判断4「歩き回りたい人は、MOD のビューとして作れる」を、本当に作れるようにする。

## 判断1: `uses` に `pointerLock` を足し、宣言した MOD の iframe にだけ `allow-pointer-lock` を付ける

**決めたこと**：

- manifest の `uses` に `"pointerLock"` を書いた MOD の iframe は、`sandbox="allow-scripts allow-pointer-lock"` になる。MOD は標準の `requestPointerLock()` を、そのまま使う
- 新しい呼び出し（`ep.…`）は作らない。`allow-same-origin` は付けないまま（ADR 0007 判断6）
- 右クリックのメニューから裏で動かす MOD（ADR 0036）には、宣言していても付けない

**検討した選択肢**：

- 案A（却下）：全 MOD の iframe に `allow-pointer-lock` を付ける。いちばん簡単だが、「宣言した機能だけが使える」（ADR 0002 判断4）に反し、入れる人にも見えない
- 案B（採用）：宣言した MOD にだけ付ける。原則どおりで、入れるときの確かめの画面にも出せる
- 案C（却下）：本体が iframe を代わりにロックし、動いた量を postMessage で MOD へ転送する。ロックは、要素を持つページ自身が頼むものなので、MOD の要素はロックできない。iframe 全体をロックして転送すると、遅れが出て、実装も重くなる

**選んだ理由**：MOD 作者は、Web の標準の書き方（Three.js の `PointerLockControls` など）がそのまま使える（ADR 0007「MOD 開発者が喜ぶ」）。
危険は小さい。Esc でブラウザが必ず外すので、マウスを奪われ続けることはなく、ファイルにも通信にも触れない。

## 判断2: ロック中は、本体のショートカットを効かせない

**決めたこと**：ロック中（`document.pointerLockElement` がある間）、ランタイムは Ctrl・Alt つきのキーと F5 を、本体へ伝えない。
WebView2 自身のショートカットと、F5・Ctrl+R の読み直しを止める処理は、ロック中も効かせる。

**選んだ理由**：ゲーム風の MOD では、Ctrl を押しながら W で走る、のような操作が普通にある。今のランタイムは Ctrl・Alt つきのキーを本体へ伝えるので、
Ctrl+W で本体のタブが閉じてしまう。ロック中はマウスも見えず、気づきにくい。

## 判断3: ロック中に本体の画面が必要になったら、先に外してもらう

**決めたこと**：ロックを外す知らせ `releasePointer` を、本体から MOD（ランタイム）へ送る。宣言したビューにだけ送る。

- そのビューのタブが隠れるとき（ほかのタブへ切り替えるとき）
- そのビューが、本体の確かめ・メニューなどの画面を出す呼び出しをしたとき（`ui.confirm`・`ui.ask`・`ui.choose`・`showMenu`・`trash`・`collections.delete`・`files.create`・`files.createShortcut`・`clipboard.paste`）
- ランタイムが自分で外す安全網：ウィンドウの `blur`、ページが `hidden` になったとき

**選んだ理由**：ロック中はポインターが消えて動かせないので、確かめの画面が出ても押せない。隠れたタブが握ったままだと、マウスが動かせなくなる。
Esc で外れるが、知らない人は困る。

**検討した選択肢**：本体の画面が開いたことを `MutationObserver` で見て、まとめて外す（却下：呼び出しの一覧のほうが、何がきっかけか読みやすく、テストしやすい。
一覧に無い画面が出ても、`blur` の安全網と Esc がある）。

## 分かっていないこと（実機で確かめる）

- WebView2（Tauri の画面の部品）で、ポインターロックが実際に使えるか（中身は Chromium なので動く見込み）
- 隠れたタブ（`display: none`）の iframe が、ロックを持ったままになるか（なっても、`releasePointer` で外す）
- 確かめ用の MOD：`spikes/pointer-lock-demo`（ホームの「開発中の MOD を追加」で、このフォルダを選ぶ）

**後で見直す条件**：ロックを外す場面が一覧から漏れて困ったとき（外す場面を足す）。MOD 作者から、ロックを許す条件をもっと細かくしたい（例：入れるときに確かめの画面を出す）と言われたとき。
