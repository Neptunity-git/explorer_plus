# 0005: リンクと仮想ディレクトリ

- 日付: 2026-10-13
- 状態: 採用中

## 判断1: 「実際の場所とは別にファイルを指し示す」仕組みを、「リンク」として1つにまとめる

**決めたこと**：次の機能は、すべて本体が持つ「リンク」という1つの仕組みで作る。ビューごとに、リンクの
見え方が違う（チェスト、線、ベン図の円など）。

- よく使うフォルダの登録（クイックアクセスのようなもの）
- 別の場所からも開けるようにする（Windows のショートカットファイルのようなもの）
- 仮想ディレクトリ（実際のパスと関係なく、ファイルを集める）
- ボクセルビューのチェスト（仮想ディレクトリの 3D での見え方）
- ブレインストーミングビューの、ファイル同士をつなぐ線
- 時間割・場所から授業のフォルダへのつながり

**検討した選択肢**：

- 案A（採用）：1つの仕組みにまとめる
- 案B（却下）：機能ごとに別々の仕組みで作る。ファイルの名前変更・移動への対応（判断2）を機能ごとに
  作ることになる。あるビューで作ったつながりが、別のビューで見えない

**選んだ理由**：発案者の「リンク機能を超充実させたい」の具体的な形になる。ADR 0002 の「1つのデータ、
たくさんのビュー」とも合う。

**後で見直す条件**：特になし。

## 判断2: リンクは、ファイルの名前変更・移動に強い形で覚える

**決めたこと**：リンクは、ファイルのパス（場所と名前）だけでなく、Windows がファイルごとに付けている
番号（ファイルID）も覚える。Windows のエクスプローラで名前を変えたり、同じドライブ内で移動したりしても、
リンクが切れないようにする。

**検討した選択肢**：

- 案A（採用）：パスとファイルID の両方を覚える
- 案B（却下）：パスだけを覚える。発案者は普段 Windows のエクスプローラも使うので、そちらで名前を変える
  だけでリンクが切れる

**選んだ理由**：仮想ディレクトリにファイルを集めても、いつの間にか空になっていたら信頼できない。

**後で見直す条件**：選んだ開発技術でファイルID が扱いにくいと分かったとき。

## 判断3: 「実物を動かした」か「リンクを置いただけ」かを、画面で区別する

**決めたこと**：仮想ディレクトリやチェストにファイルを入れても、実際のファイルは動かない。
画面上では、実物とリンクを見た目で区別できるようにする。

**検討した選択肢**：

- 案A（採用）：見た目で区別する
- 案B（却下）：区別しない。チェストに入れたら実物が動いた（または動いていない）と勘違いし、ファイルを
  探せなくなる

**選んだ理由**：仮想ディレクトリは便利だが、実際の場所との関係が分からなくなると、かえって混乱を招く。

**後で見直す条件**：特になし。

## 判断4: 仮想ディレクトリはビューごとに別々に持つ（パラレル）

**決めたこと**：仮想ディレクトリの構造（どのファイルを集めたか、どこに置いたか）は、ビューごとに別々に持つ。
ビューの数だけ構造が生まれる。ボクセルビューのチェストに入れても、ブレインストーミングビューには現れない。
「リンク」の仕組み（判断1・2。名前変更・移動に強いファイルの指し示し方）は、本体が全ビューに共通で提供する。
よく使うフォルダの登録・キーボード操作・時間割のつながりは、ビューに属さず、アプリ全体で1つ。

**検討した選択肢**：

- 案A（採用）：ビューごとに別々の構造（パラレル）
- 案B（却下）：「どのファイルを集めたか」は全ビュー共通で、「どこに置いたか」だけビューごと。ビューごとに
  向いている整理の仕方が違う（チェストは箱に分ける、ブレインストーミングは線でつなぐ）のに、同じ集まり方を
  押しつけることになる。MOD のビューが、他のビューの構造を勝手に変えてしまうおそれもある

**選んだ理由**：発案者の判断。ビューごとに自由な構造を持てるほうが、MOD 作者が新しい整理の仕方を発明できる。
MOD が触れるのは自分の構造だけになるので、安全面でも都合がよい（ADR 0002 判断3）。

**後で見直す条件**：「別のビューで作った構造を、こちらのビューでも使いたい」という要望が出たとき
（他のビューの構造を読み取り専用で参照できるようにする、など）。

## 用語メモ

- パス：ファイルの場所と名前を表す文字列。例：`C:\Users\neo_m\Documents\report.docx`
- 仮想ディレクトリ：実際にはそこにないファイルを、このアプリの中でだけ1つのフォルダのように集めて見せるもの
- ファイルID：Windows（NTFS という仕組み）がファイルごとに付けている番号。同じドライブの中なら、名前を
  変えても移動しても変わらない
- ボクセル：小さな立方体のこと。マインクラフトの世界のように、立方体を積んで作る見た目
