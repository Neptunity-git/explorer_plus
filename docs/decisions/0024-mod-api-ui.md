# 0024: MOD の API を広げる（2）本体の画面を使う

- 日付: 2026-10-15
- 状態: 採用中

ADR 0023 の続き。MOD が自分の画面の中だけでなく、本体の画面（お知らせ・確かめの画面・タブ・状態の欄・設定・コマンド）も使えるようにする。

## 判断1: お知らせ・確かめ・入力・選択・タブのバッジ・状態の欄を、本体が出す

- `ui.toast`・`ui.status`・`ui.tab`・`ui.confirm`・`ui.ask`・`ui.choose`。見た目は本体のものと同じ（どの MOD でも同じ手触り）
- uses の宣言は要らない（ファイルにも情報にも触れないため）
- ただし、裏のタブから急に画面が出ないよう、お知らせ・確かめの画面は**表示中のタブのビューだけ**。確かめの画面は同時に1つまで、お知らせは 0.3 秒に1回まで

## 判断2: MOD の設定は、manifest に項目を書くと本体が画面を作る

- 種類は boolean・number・text・choice・color。値は本体が覚え、`settings.get` と知らせ `settings` で渡す
- 開く場所：タブの ▸ のメニュー、タブの右クリック、コマンドの一覧
- 選んだ理由：MOD ごとに設定の画面を作る手間をなくし、どの MOD でも同じ場所・同じ見た目で設定できるようにする（ADR 0007「MOD 開発者が喜ぶ」）

## 判断3: コマンドの一覧（Ctrl+Shift+P）

- 表示中のビューのコマンド（`commands.set`）と、本体のコマンド（新しいタブ・このビューの設定・ビューを変える）を、打って絞り込める一覧に出す
- VS Code と同じキー。WebView2 がこのキーを「印刷」に使っていたので、本体とランタイムで WebView2 自身のショートカット（印刷・ページ内検索・保存など）を止めた
