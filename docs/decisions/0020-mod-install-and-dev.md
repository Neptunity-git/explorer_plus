# 0020: MOD を入れる窓口・作る道具・開発者向けの説明書

- 日付: 2026-10-15
- 状態: 採用中

インストーラを作る前に、「MOD を作って、配って、入れる」ができるようにする（発案者の判断）。

## 判断1: MOD は zip で配り、ホームの「MOD」の欄で入れる

**決めたこと**：MOD のフォルダを zip にまとめて配る（専用の拡張子は作らない）。ホームの「MOD を入れる」で zip を選ぶか、
ホームのタブ（フォルダと関係ないタブ）に zip を落とすと入る。入れる前に本体が確かめの画面を出す：名前・版・説明・
「このビューが使う情報」（uses を日本語にしたもの）・ファイルの数と大きさ・「MOD はファイルの変更やネット通信を自分ではできない」。
同じ id がもう入っていれば「更新」として見せ、古いフォルダはごみ箱へ送って置き換える。外すときもフォルダはごみ箱へ。
MOD が保存していたもの（storage）は残す（入れ直せば続きから使える）。

zip は一時の場所に展開して調べてから移す。中のパスが外を指すもの（`..` など）は拒む。ファイルは 2000 個・展開して 50MB まで。

**検討した選択肢**：zip（採用）／専用の拡張子 .epmod（却下：作る人に名前の付け替えの手間。後でダブルクリックで入れたくなったら足せる）

## 判断2: 作る人のために、ひな形・開発中の MOD・ホットリロード・zip にする道具をアプリに入れる

**決めたこと**：

- **ひな形から作る**：名前と場所を選ぶと、同梱のひな形（大きさの棒グラフのビュー・型の定義・jsconfig.json・説明書）を
  コピーし、id を `my.<名前>` にして、開発中の MOD として登録し、そのフォルダを新しいタブで開く
- **開発中の MOD**：好きな場所のフォルダを登録して読み込む（`dev-mods.json`）。入れた MOD より先に読む（同じ id なら開発中のもの）
- **ホットリロード**：開発中の MOD のフォルダを見張り、保存されたら、その MOD を使っているタブのビューを作り直す（フォルダと履歴はそのまま）
- **zip にする**：開発中の MOD を、フォルダの隣に `id-版.zip` としてまとめる。node_modules・.git・作る人だけが使うファイルは入れない
- **開発者ツール**：インストールした版でも開けるようにする（Tauri の devtools）。ホームから開ける。MOD のエラーを見るため

**選んだ理由**：「MOD 開発者が最大限喜ぶ」（ADR 0007）。保存したらすぐ見える、が一番効く。

## 判断3: MOD の管理は、標準のビューだけが使える API（mods.*）にする

**決めたこと**：ホームビューが使う `ep.mods.*`（一覧・入れる・外す・開発中の MOD・zip にする・説明書・開発者ツール）と、
知らせ `mods` を足す。id が `builtin.` で始まる標準のビューだけが使え、ほかの MOD が呼ぶと `denied`。
ファイルを選ぶ画面と確かめの画面は本体が出す（MOD は「出して」と頼むだけ）。

**選んだ理由**：MOD が勝手にほかの MOD を入れ替えられると、安全の約束（ADR 0007）が崩れる。

## 判断4: 開発者向けの説明書は、アプリに同梱する

> **ADR 0021 判断2 で更新**：元は Markdown（guide.md）にし、HTML はそこから自動で作る。ひな形には MD を入れる。

**決めたこと**：「MOD 開発ガイド」を1つの HTML（`work/app/mod-docs/index.html`）にして同梱し、ホームから既定のブラウザで開く。
ひな形のフォルダにも同じものを入れる。今のリポジトリは非公開なので、公開の場所は後で決める。
（ADR 0035 で更新：リポジトリは公開した。説明書は `work/app/mod-docs/guide.md` として GitHub でも読める）

**後で見直す条件**：MOD を作る人が増えて、MOD を探せる場所（一覧のサイト）や、公開の説明書が欲しくなったとき。
