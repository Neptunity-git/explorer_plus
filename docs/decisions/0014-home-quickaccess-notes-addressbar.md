# 0014: 場所と関係ないビュー／ホーム／クイックアクセス／ノート／アドレスバー／画像の縮小表示

- 日付: 2026-10-14
- 状態: 採用中

発案者が実際に触って出した要望（2026-10-14）をまとめて決めたもの。

## 判断1: ビューは「フォルダと関係するか」を manifest で宣言する

**決めたこと**：manifest に `location` を足す。`"folder"`（既定。今のフォルダを見せる）か `"none"`（フォルダと関係ない。タグビュー・ホームなど）。
`"none"` のビューのタブでは、アドレスバーと戻る・進む・上へを隠し、タブの名前をビューの名前にする。

**検討した選択肢**：

- 案A（採用）：manifest で宣言する
- 案B（却下）：本体が標準ビューの id を見て決める。MOD 作者が「フォルダと関係ないビュー」を作れない

**選んだ理由**：発案者の指摘（「タグビューでは今の居場所は関係ない」）。MOD 作者にも同じことができる。

**後で見直す条件**：特になし。

## 判断2: 新しいタブは「ホーム」ビューで開く

**決めたこと**：Win11 のエクスプローラと同じく、新しいタブは「ホーム」で開く。ホームでは、どのビューで開くかを選べ、クイックアクセスと最近使った項目を出す。
今の授業は出さない（アドレスバーの横のボタンで足りる）。ホームも標準ビュー（MOD と同じ形）で作る。

**検討した選択肢**：

- 案A（採用）：ホームを標準ビューとして作る
- 案B（却下）：ホームを本体の画面として作る。MOD 作者が自分好みのホームを作れない（ADR 0002 判断2「標準ビューも MOD と同じ決まりで作る」）

**選んだ理由**：発案者の希望（Win11 のホームのように）。ビューを選んでから開ける入口になる。

**後で見直す条件**：特になし。

## 判断3: クイックアクセスは本体の左の欄に置く

**決めたこと**：右クリックのメニューの「クイックアクセスにピン留め」で登録したフォルダを、本体の左の欄（よく使う場所の上）に並べる。アプリ全体で1つで、
どのビューからも使える。これを、以前決めた「よく使うフォルダの登録」（ショートカットの1つ）とする。MOD からも読み書きできる（ホームで使う）。

**検討した選択肢**：

- 案A（採用）：本体の左の欄
- 案B（却下）：Win11 風ビューの中だけに置く。ほかのビューを開いているときに使えない

**選んだ理由**：よく使うフォルダへの移動は、どのビューを開いていても欲しい。

**後で見直す条件**：特になし。

## 判断4: ノートビューは、フォルダごとに1ページ。アプリの中に保存する

> **ADR 0019 で置き換え**：ノートビューは、付箋・子フォルダ・描いた線を自由に置ける平面にした。保存の仕方（フォルダのファイルID ごと）はそのまま。

**決めたこと**：ノートビューは、開いているフォルダのノートを見せて、その場で書ける。ノートはアプリの中（ノートビューの保存場所）に、フォルダのファイルID ごとに保存する。

**検討した選択肢**：

- 案A（採用）：アプリの中に保存
- 案B（却下）：フォルダの中にファイル（`.note.md` など）として保存。OneDrive の共有で相手にも見えるが、どのフォルダにもファイルが増える。
  また、MOD はファイルを書けない（ADR 0002 判断3）ので、本体に特別な機能が要る

**選んだ理由**：発案者の判断。フォルダを汚さず、ファイルID で覚えるので名前変更・移動にもついてくる（ADR 0005 判断2）。

**後で見直す条件**：ノートを人と共有したくなったとき（書き出しの機能を足す）。

## 判断5: アドレスバーは Win11 と同じ。区切りごとに押せて、コマンドも起動できる

**決めたこと**：アドレスバーは、パスを区切りごとのボタンで見せ（パンくずリスト）、押すとその階層へ移動する。空いている所を押すと、文字の入力に変わる。
入力した文字がフォルダでもファイルでもなければ、コマンド（`cmd`・`powershell`・`code .` など）として、今のフォルダを作業場所にして起動する。

**検討した選択肢**：

- 案A（採用）：Win11 と同じ
- 案B（却下）：コマンドの起動は入れない。Win11 で `cmd` と打つ使い方に慣れた人が困る

**選んだ理由**：発案者の希望。Win11 で指が覚えている使い方を受け継ぐ（ADR 0009 判断1）。

**後で見直す条件**：特になし。

## 判断6: 画像は、Win11 風ビューの「大アイコン」表示で縮小画像を並べる

**決めたこと**：Win11 風ビューに表示の切り替え（詳細／大アイコン）を足す。大アイコンでは、Windows が作る縮小画像（サムネイル）を出す。
縮小画像は本体が `http://icon.localhost/thumb?…` から配る（MOD の Entry に `thumbnailUrl` を足す）。

**検討した選択肢**：

- 案A（採用）：大アイコン表示で縮小画像
- 案B（保留）：画像を開くと、アプリの中に大きく表示する。発案者は案A を選んだ。必要になったら足す

**選んだ理由**：発案者の判断。Win11 と同じ見え方で、たくさんの画像を見比べられる。Windows の縮小画像の仕組みを使うので、画像以外（PDF・動画）にも効く。

**後で見直す条件**：画像を大きく見たい、という要望が出たとき（案B）。

## 判断7: OneDrive の共有は、Windows 本来の右クリックのメニューで出す（先に試作で確かめる）

> **ADR 0016 判断2 で確定**：試作で確かめ、OneDrive の項目を本体のメニューから呼び出す形にした。

**決めたこと**：OneDrive の「共有」は、OneDrive が Windows の右クリックのメニューに足している項目。本体のメニューに「その他のオプションを表示」を置き、
Windows 本来のメニュー（ADR 0009 判断2 案C）を出せるようにして、そこから共有する。Windows の COM の仕組みを使うので、先に小さな試作で動くか確かめる。

**検討した選択肢**：

- 案A（採用）：Windows 本来のメニュー
- 案B（却下）：Microsoft Graph（OneDrive の API）で共有のリンクを作る。Microsoft のアカウントでのログインの仕組みを作る必要があり、大きい。
  共有の相手を選ぶ画面も自作になる
- 案C（却下）：OneDrive の共有だけを個別に呼ぶ。決まった呼び方が公開されていない

**選んだ理由**：OneDrive の共有だけでなく、7-Zip など、ほかのアプリが足した項目もまとめて使えるようになる。

**後で見直す条件**：試作で、Windows 本来のメニューがこのアプリから出せないと分かったとき（案B を考える）。

## 用語メモ

- パンくずリスト：`C: > Users > neo_m` のように、今いる場所までの道のりを区切って並べたもの。押すとその階層へ戻れる
- サムネイル：画像やファイルの中身を小さく縮めた絵
- ピン留め：よく使うものを、いつも見える場所に留めておくこと
