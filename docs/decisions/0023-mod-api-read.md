# 0023: MOD の API を広げる（1）読み取り

- 日付: 2026-10-15
- 状態: 採用中

## きっかけ

発案者の方針：「土台を完成させ、ボクセルも樹形図も何もかも MOD で作れるようにする。MOD の API を超充実させる」。
API を4つの組に分けて順に足す：(1) 読み取り（この ADR）、(2) 本体の画面を使う、(3) 書き込み・コレクション、(4) 通信。

## 判断1: ファイルの中身・詳しい情報・検索と集計・PC の情報・変化の知らせを、読み取りの API として足す

| uses | できること |
|---|---|
| `fileContent` | 文章として読む（文字コードを見分ける）、バイトで読む、画面に出す URL（画像・動画・音楽・3D の模型・フォント） |
| `fileInfo` | 撮影日時・撮影場所・カメラ、曲名・アーティスト・長さ、動画の縦横・長さ・フレームレートなど |
| `search` | 下の階層までの検索（名前・拡張子・大きさ・日付・中身の文字）と集計（数・大きさ・拡張子ごと・大きいもの・新しいもの） |
| `system` | ドライブと空き容量、Windows の強調色、言語 |
| （entries） | 開いているフォルダの直下の変化を1件ずつ（作られた・消えた・名前が変わった・書き換わった） |

**作り方**：

- 詳しい情報は、形式を自分で読み解かず、Windows のプロパティ（エクスプローラの「詳細」と同じもの）に任せる（ADR 0004）
- ファイルの URL は、本体がファイルID を確かめた項目にだけ、推測できないランダムな印で発行する（4000 個まで覚え、古いものから無効）。
  動画・音楽のシークのため Range に対応。HTML やスクリプトは文字として返す（ページとして動かさない）
- 検索・集計はリンク（ジャンクション）の先へ入らない。数・時間に上限（30 万項目・20 秒）。中身の検索は文章のファイル（4MB まで）だけで、
  OneDrive の「クラウドにだけある」ファイルは読まない（勝手にダウンロードしない）
- どれも uses の宣言が要る。入れるときの確かめの画面に「使う情報」として出る

**安全**：読むだけで、ファイルを変えることはできない。通信は (4) まで禁止のまま。

## 判断2: 書き込みは「新規作成だけ・最初に許可を取る」、通信は「宛先を manifest に書き、入れるときに許可」（後の組で作る）

発案者の判断。書き込みは新しいファイル・フォルダを作ることだけ（上書きしない）。MOD ごとに、最初に使うとき本体が許可を聞く。
通信は、使う宛先（https の origin）を manifest に書き、入れるときの確かめの画面で見せて許可を取る。MOD のコードは宛先から読み込めない。
ファイルの中身を読める MOD が通信もできる場合は、確かめの画面で強く警告する（中身が外へ送られる恐れがあるため）。
