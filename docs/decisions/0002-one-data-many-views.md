# 0002: 1つのデータ、たくさんのビュー（MOD で追加できる）

- 日付: 2026-10-13
- 状態: 採用中

## 判断1: データとビューを分け、ビューを差し替えられる作りにする

**決めたこと**：ファイル・時間割・メモ・共有相手の情報は、本体が1か所で持つ。ビュー（2D リスト・
3D ジオラマ・ベン図など）は、そのデータを読んで描くだけにする。ビューは即座に切り替えられる。

**検討した選択肢**：

- 案A（採用）：データとビューを分ける
- 案B（却下）：2D 画面と 3D 画面を別々に作り込む。最初は早いが、ビューを増やすたびに、データの読み方や
  更新の仕方を作り直すことになる。発案者の理想（「同じデータを参照するが、ビューの種類がたくさんある」）
  を実現できない

**選んだ理由**：ビューを増やすことがこのアプリの魅力そのものなので、増やしやすい作りを最初から選ぶ。

**後で見直す条件**：特になし（アプリの芯なので、変えるなら作り直しになる）。

## 判断2: 標準のビューも、MOD と同じ決まり（API）で作る

**決めたこと**：最初から入っているビューも、ユーザーが作る MOD と同じ API で作る。
MOD の読み込み機能そのものは第5段階で入れるが、API は第1段階から意識する。

**検討した選択肢**：

- 案A（採用）：標準のビューも MOD と同じ API で作る
- 案B（却下）：標準のビューは本体の中で自由に作り、MOD 用の API は後で別に用意する。標準のビューで
  できることが MOD ではできない、という差が生まれやすく、後から API を足すと大きな作り直しになる

**選んだ理由**：自分たちで作れたビューは MOD 作者も作れる、と保証できる。API の足りない点にも早く気づける。

**後で見直す条件**：API を通すと表示が遅すぎると分かったとき。

## 判断3: MOD のビューは「読んで描くだけ」に制限する

**決めたこと**：MOD のビューは、データを読んで描くことだけができる。ファイルの変更・削除や、
ネットとの通信はできない。削除などの操作を頼むときは本体を通し、本体が確認する。

**検討した選択肢**：

- 案A（採用）：読んで描くだけに制限し、隔離された場所（サンドボックス）で動かす
- 案B（却下）：MOD に本体と同じ権限を与える。他人が書いた MOD が、勝手にファイルを読んで外へ送ったり、
  消したりできてしまう

**選んだ理由**：MOD を気軽に試せることと、自分のファイルが守られることの両方が必要。

**後で見直す条件**：「ファイルを操作する MOD」を作りたい要望が出たとき（その操作だけを、ユーザーが
許可する形で開ける）。

## 判断4: ビューは「どの情報を使うか」を宣言する

**決めたこと**：ビューが参照できる情報（フォルダの階層、名前・種類・サイズ・更新日時、時間割、メモ、
共有相手など）は全ビュー共通。ただし各ビューは、実際に使う情報を宣言し、本体は宣言された情報だけを
用意して渡す。

**検討した選択肢**：

- 案A（採用）：ビューが使う情報を宣言する
- 案B（却下）：すべての情報を、すべてのビューに常に渡す。フォルダのサイズのように、中身を全部数えないと
  分からない重い情報まで、使わないビューのために毎回計算することになる。MOD がどの情報を読むのかも
  分からない

**選んだ理由**：発案者の指摘のとおり、ビューごとに使う情報には偏りがある（樹形図は親子関係、ベン図は
共有相手、Win11 風はサイズや更新日時）。宣言させれば、重い計算を必要なときだけにでき、MOD を入れる前に
「この MOD は何を読むか」をユーザーに見せられる（スマホアプリの権限表示と同じ考え方）。

**後で見直す条件**：宣言の仕組みが MOD 作者にとって面倒すぎると分かったとき。

## 判断5: ビューはタブごとに選べる

**決めたこと**：Windows 11 のエクスプローラのタブ機能を受け継ぐ。タブごとに表示するビューを選べる
（タブ1は Win11 風、タブ2は樹形図、など）。

**検討した選択肢**：

- 案A（採用）：タブごとにビューを選ぶ
- 案B（却下）：ビューはアプリ全体で1つ。タブを切り替えるたびにビューも切り替え直すことになる

**選んだ理由**：発案者が Windows 11 のタブ機能を気に入っている。タブとビューを組み合わせると、
同じフォルダを2つの見せ方で並べて見られる。

**後で見直す条件**：特になし。

## 用語メモ

- ビュー：同じデータの「見せ方」。2D のリスト、3D の模型、ベン図など
- MOD：ユーザーが作ってアプリに追加する部品。ゲームの改造データ（MOD）と同じノリ
- API：部品同士がやりとりするための約束事。「ビューにはこの形でデータを渡す」「ビューは本体にこう頼む」など
- サンドボックス：プログラムを隔離された場所で動かし、許可したこと以外をできなくする仕組み
