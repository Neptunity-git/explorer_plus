# 0038: ログを「ファイル」として使えるようにする（置き場所は変えず、開く・書き出す）

- 日付: 2026-10-22
- 状態: 採用中（ADR 0029 に追加）

**困りごと**：MOD の `console.log` は、ホームの「ログ」の欄で見られる。でも、ファイルとして欲しい時がある（人や AI に渡す、検索する、別のアプリで開く）。
実は、ログはもうファイルにも残っている（アプリのデータの `logs/mod.<id>.log`）が、見つけにくく、中身が1行1件の JSON なので、そのまま読んだり渡したりしにくい。

発案者の案は「ホームの表示はそのままで、裏で、MOD のフォルダの中にあるログファイルを参照する形」。

## 判断1: ログの置き場所は、MOD のフォルダの中にせず、今の `logs` フォルダのままにする

**決めたこと**：ファイルの置き場所は変えない。ホームの表示も今までどおり（ファイルが元で、新しい分がメモリに流れてくる）。

**検討した選択肢**：

- 案A（採用）：置き場所はそのまま。「ファイルで開く」「ログのフォルダ」を足して、ファイルとして使えるようにする
- 案B（却下）：ログを MOD のフォルダの中に置く。次の問題がある
  - **開発中の MOD で、読み直しが止まらなくなる**：本体は開発中のフォルダを見張っていて、中身が変わるたびに MOD を読み直す（`watch_dev`）。ログを書くたびに変更とみなされ、読み直しでまたログが増える
  - **入れ直す・更新すると、ログが消える**：入れ直すときは、古いフォルダを丸ごとごみ箱へ送る（`mod_install`）。更新の直後は、新しい版が動くか見たいので、一番ログが欲しい時
  - **zip にログが混ざる**：「MOD を zip にする」は `node_modules`・`.git` 以外を全部入れる。開発フォルダが Git の管理下なら、`.gitignore` も要る
  - **標準の MOD は書き込めない**：インストールされたアプリの中にあり、書き込めない場所
- 案C（保留）：開発中の MOD だけ、`logs` を見張りと zip の対象から外したうえで、フォルダの中にも写す。案Aで足りなければ検討する

## 判断2: 読みやすいファイルは、ボタンで書き出す（保存形式は変えない）

- ホームのログ欄に2つ足す：
  - 「ファイルで開く」：見ている出どころのログを、人が読む文字のファイル（`logs/app.txt`・`logs/mod.<id>.txt`）に書き出し、PC の既定のアプリ（メモ帳など）で開く。「出す重さ」で絞っているときは、絞ったものだけ（「コピー」と同じ）
  - 「ログのフォルダ」：`logs` フォルダを、アプリの新しいタブで開く（元の `*.log` も、書き出した `*.txt` も入っている）
- 書き出す形は、1件が1行：`2026-10-22 12:34:56.789 [warn] 本文`（この PC の時刻）。本文が何行かあるときは、2行目から4文字ぶん字下げ。改行は `\r\n`（メモ帳でもそのまま読める）
- 保存形式（1行1件の JSON）は変えない。これまでのログがそのまま読める。書き出しは毎回ファイルを置き換える（ログそのものではなく、写し）
- 「消す」は、書き出した `.txt` も消す
- 書き出せるのは、画面に覚えている分（新しい方から 1000 件まで）。ファイルには 1MB まで残るが、書き出しの対象は覚えている分

**検討した選択肢**：

- 保存するファイルそのものを、読みやすい文字の形に変える（却下：本文に改行があっても1件が壊れない JSON のほうが、読み戻しが確実。形を変えると、今のログの読み込みも作り直しになる）
- 保存先を選ぶ画面を出す（却下：まず固定の場所で足りる。「ログのフォルダ」から、ドラッグ・コピーで持ち出せる）

## 判断3: 新しい API は標準のビュー（ホーム）だけが使える

- `logs.openFile({ source, level? })`・`logs.openFolder()`（ADR 0029 の `logs.*` と同じく、ほかの MOD が呼ぶと `denied`。ほかの MOD のログを読めないようにする決まりのまま）
- `ep.logs.openFile(source, level)`・`ep.logs.openFolder()`

## ついでに直したこと

`mod.<id>.log` から `.old.log` の名前を作るとき、id に `.log` が入っている MOD（`my.logger` など）だと、名前の途中も置き換えてしまい、
1MB を超えたときの入れ替え先と、「消す」で消す古いファイルの名前がずれていた。後ろの拡張子だけを替えるようにした。

**後で見直す条件**：「ファイルで開く」を何度も使う・保存先を選びたい、と感じたとき（保存先の選択、案C）。
