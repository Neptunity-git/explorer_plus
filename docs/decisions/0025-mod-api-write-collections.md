# 0025: MOD の API を広げる（3）新しく作る・コレクション

- 日付: 2026-10-15
- 状態: 採用中

## 判断1: MOD は「新しく作る」だけができる。MOD ごとに、最初に使うとき許可を聞く

発案者の判断（ADR 0023 判断2）。

- `files.create`（ファイル・フォルダ。中身は文字かバイト）と `files.createShortcut`（.lnk）。**上書きしない**：同じ名前があれば `exists`
- 今あるファイルを書き換える・消す API は作らない（消すのは今までどおり、本体が確かめる `trash`）
- MOD ごとに、最初に使うときだけ本体が「許可しますか？」と聞き、覚えておく。MOD を外すと許可も消える。標準のビューは聞かない
- 名前は Windows で使えるものだけ（使えない文字・CON などの予約された名前・末尾の点と空白を拒む）

**検討した選択肢**：新規作成だけ・初回に許可（採用）／毎回確認（却下：たくさん作るビューで使いにくい）／まだ許さない（却下）

## 判断2: コレクション（仮想ディレクトリ）を、アプリ全体の共有のデータとして API にする

ADR 0005「仮想ディレクトリはパラレル（実際のフォルダと並ぶ別の並べ方）」を、MOD から使える形にした。

- ファイル・フォルダを場所と関係なく集めて名前・色を付けたもの。中身はファイルID で覚える（名前変更・移動に強い。見つけたら覚えているパスも直す）
- アプリ全体で1つ。どの MOD からも同じコレクションが見える（ボクセルビューのチェストも、樹形図ビューの枝も、同じ集まりを別の見せ方で出せる）
- 消すときは本体が確かめる（中のファイルは消えない）

**後で見直す条件**：MOD ごとに自分だけのコレクションが欲しくなったとき（今は `storage`・`folderData` で代わりにできる）。左の欄にコレクションを出したくなったとき。
