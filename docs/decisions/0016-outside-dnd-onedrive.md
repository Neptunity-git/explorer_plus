# 0016: アプリの外とのドラッグ＆ドロップ／OneDrive の操作／以前の形式の時間割を捨てる

- 日付: 2026-10-14
- 状態: 採用中

## 判断1: 普通のエクスプローラなど、アプリの外とのドラッグ＆ドロップを、Windows の仕組みで行う

**決めたこと**：

- 外から中へ：Windows がアプリの窓に渡す「ファイルが落とされた」知らせ（Tauri のドラッグ＆ドロップの知らせ）を本体が受け取り、
  アプリの中のドラッグ（ADR 0015 判断2）と同じく、落とせる場所を光らせる。落とすと、ADR 0015 判断1 と同じ Windows の仕組みで移動・コピーする。
  移動とコピーの決まりも同じ（同じドライブなら移動、別のドライブならコピー）。外から来たファイルにはファイルID が無いので、パスで扱う（本体の画面だけが使え、MOD は使えない）。
- 中から外へ：アプリの中でドラッグしている項目が、窓の外へ出たところで、Windows のドラッグ（OLE の DoDragDrop）に切り替える。
  渡すデータは、エクスプローラで選んだときと同じもの（項目のまとまりから Windows に作ってもらう）。移動・コピーは落とした先（エクスプローラなど）が行う。

**検討した選択肢**：

- 案A（採用）：Windows の仕組みを使う。普通のエクスプローラ・デスクトップ・ほかのアプリ（メールの添付など）とも行き来できる
- 案B（却下）：外へのドラッグを、ドラッグ用の部品（Tauri の追加機能）に任せる。依存が増えるうえ、ビューの中（iframe）から始まるドラッグとのつなぎは結局自作になる

**選んだ理由**：Windows が得意なことは Windows に任せる（ADR 0004）。エクスプローラと同じデータを渡すので、落とした先の動きが普段の Windows と同じになる。

**分かったこと**：移動のときは、落とした先が自分で移動を行い、結果は「何もしない」と返ってくる（Windows の決まり）。そのため、本体は「落とされたか」で判断して画面を読み直す。

**後で見直す条件**：外へドラッグするときに、Ctrl・Shift でコピー・移動を選べない、などの不便が出たとき。

## 判断2: OneDrive の操作は、Windows 本来の右クリックのメニューの項目を呼び出す

**決めたこと**：OneDrive の中のファイル・フォルダを右クリックすると、本体のメニューに「OneDrive で共有…」「OneDrive のリンクをコピー」
「OneDrive のアクセス許可の管理…」「オンラインで表示」を出す。選ぶと、Windows 本来のメニュー（シェルのメニュー）から OneDrive の項目を探して呼び出す。
画面は OneDrive が出す。項目は OneDrive の名前（verb）で探し、見つからなければ表示の文字で探す。OneDrive の中かどうかは、環境変数 OneDrive などの下にあるかで判断する。

**検討した選択肢**：

- 案A（採用）：OneDrive の項目を名前で探して呼ぶ。本体のメニューの見た目のまま使える
- 案B（却下）：Windows 本来のメニューを丸ごと出す。項目が多すぎ、「メニューはこのアプリならではの項目に絞る」（ADR 0015 判断1）と合わない
- 案C（却下）：OneDrive の仕組み（Microsoft Graph）を直接使う。サインインと通信を自作することになる

**選んだ理由**：共有の画面・相手の選び方・権限は、OneDrive のものが一番正しく、慣れている。ADR 0014 判断7 の試作で、項目の名前と呼び出しが動くことを確かめた。

**後で見直す条件**：OneDrive の版が変わって項目が見つからなくなったとき。ほかのクラウド（Google ドライブなど）の項目も出したくなったとき。

## 判断3（小）: 以前の形式の時間割（アプリ全体で1つ）は、移さずに捨てる

発案者の判断。以前の形式の時間割（app-data/timetable.json）は読み込まず、移す機能も作らない。発案者の PC のファイルは削除した。
