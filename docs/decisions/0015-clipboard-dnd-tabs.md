# 0015: 切り取り・コピー・貼り付け／ドラッグ＆ドロップ／タブの並べ替え／時間割のメモ

- 日付: 2026-10-14
- 状態: 採用中

## 判断1: 切り取り・コピー・貼り付けは、Windows のクリップボードと同じ形式でやりとりし、実際の操作は Windows に任せる

**決めたこと**：切り取り・コピーは、Windows のエクスプローラと同じ形式（ファイルの一覧 CF_HDROP と、「切り取りかコピーか」の印）でクリップボードに入れる。
貼り付けは、クリップボードのファイルを今のフォルダへ、Windows のファイル操作の仕組み（IFileOperation）でコピー・移動する。進み具合・同じ名前があるときの画面は Windows のものが出る。
キーは Win11 と同じ（Ctrl+X・Ctrl+C・Ctrl+V）。右クリックのメニューには出さない（発案者の判断：知っていて当然の操作で、
このアプリは普通のエクスプローラで満足できない人向けなので、メニューは「このアプリならでは」の項目に絞る）。

**検討した選択肢**：

- 案A（採用）：Windows と同じ形式・Windows の仕組み
- 案B（却下）：このアプリの中だけで覚えておき、自分でコピー・移動する。Windows のエクスプローラとの間で貼り付けられない。進み具合・名前の重なりの画面を自作することになる
  （発案者は「GUI を作る必要はない」と判断した）

**選んだ理由**：普段の Windows と行き来できる。大きなファイルのコピーの進み具合や、同じ名前のときの選び方を、慣れた Windows の画面で扱える（ADR 0004「Windows が得意なことは Windows に任せる」）。

**後で見直す条件**：Windows の画面がアプリの見た目と合わず、気持ちいいアニメーション（ADR 0003）を付けたくなったとき。

## 判断2: ドラッグ＆ドロップは、本体がアプリの中のドラッグを受け持つ

**決めたこと**：ビューの中で項目をドラッグし始めると、ビューは本体に「この項目をドラッグし始めた」と知らせ、落とせる場所（フォルダの行の位置）も渡す。
そこから先は本体がマウスを追い、落とせる場所（ビューの中のフォルダ、アドレスバーの区切り、左の欄、タブ）を光らせる。タブの上で少し止めると、そのタブに切り替わり、
そのビューの落とせる場所も使えるようになる。落としたら、本体が判断1 と同じ Windows の仕組みで移動・コピーする。

移動とコピーの決まりは Win11 と同じ：同じドライブなら移動、別のドライブならコピー。Ctrl を押していればコピー、Shift を押していれば移動。
自分自身や自分の中のフォルダへは落とせない。

**検討した選択肢**：

- 案A（採用）：本体がマウスを追う（ビューの上に透明な幕を敷く）
- 案B（却下）：ブラウザのドラッグ＆ドロップ（HTML5）を使う。Tauri がアプリの外からのファイルのドロップを受け取るために、ウィンドウの中のブラウザのドラッグ＆ドロップを止めており、
  使うと外からのドロップでパスが取れなくなる。また、MOD の iframe（出どころ null）と本体の間で、ドラッグの中身を安全にやりとりしにくい
- 案C（今回は入れない）：Windows のドラッグの仕組み（OLE）で、アプリの外（Windows のエクスプローラ・デスクトップ）との間でもドラッグできるようにする。Rust で COM の
  ドラッグを扱う必要があり大きいので、後で足す

**選んだ理由**：アドレスバー・タブ・左の欄・ビューの中を、1つの仕組みで行き来できる（発案者の希望）。ビューは、ドラッグの始まりと落とせる場所を伝えるだけでよく、MOD 作者の手間が少ない。

**後で見直す条件**：アプリの外とのドラッグ＆ドロップが欲しくなったとき（案C）。

## 判断3: タブはドラッグで並べ替えられる。動きは滑らかにする

**決めたこと**：タブをドラッグすると、まわりのタブが滑らかに避け、離した位置に入る。

**検討した選択肢**：

- 案A（採用）：滑らかに避ける
- 案B（却下）：離した位置に、いきなり入れ替える。どこに入るかが、離すまで分からない

**選んだ理由**：発案者の希望（「スムーズにやりたい」）。ワクワクの柱（ADR 0001）。

**後で見直す条件**：特になし。

## 判断4: 時間割のコマとオンデマンドの授業に、短いメモを付けられる

**決めたこと**：コマとオンデマンドの授業に、`memo`（0〜200 文字）を持たせる。コマの中に小さく出し、右クリックの「メモ…」で書く。

**検討した選択肢**：

- 案A（採用）：コマごとの短いメモ
- 案B（却下）：ノートビューを使う。授業のフォルダのノートは長い記録向けで、時間割の表を見ながら一目で分かる「教室・持ち物」のような短い情報には向かない

**選んだ理由**：発案者の希望（「ちっちゃいメモ機能は時間割に欲しい」）。

**後で見直す条件**：特になし。

## 判断5: 右クリックのメニューは「このアプリならでは」と、基本の操作でもメニューが便利なものに絞る

**決めたこと**：項目を右クリックしたときのメニューから「開く」を外し（ダブルクリック・Enter で足りる）、ファイルには「プログラムから開く…」を足す
（Windows の「アプリを選ぶ」画面を出す）。「パスのコピー」は残す。切り取り・コピー・貼り付けは出さない（判断1）。

**検討した選択肢**：

- 案A（採用）：発案者が項目ごとに選んだ形
- 案B（却下）：Win11 と同じく、基本の操作もすべてメニューに並べる。このアプリは普通のエクスプローラで満足できない人向けで（企画書の対象ユーザー）、
  知っていて当然の操作が並ぶと、このアプリならではの項目（タグ・時間割・クイックアクセスなど）が埋もれる

**選んだ理由**：発案者の判断。キーで足りる操作はメニューから外し、キーでは分かりにくい操作（どのアプリで開くか、パスの文字）は残す。

**後で見直す条件**：特になし。

## 用語メモ

- クリップボード：コピーしたものを一時的に置いておく、Windows 全体で共通の場所
- CF_HDROP：Windows のエクスプローラが、ファイルのコピー・切り取りでクリップボードに入れる形式（ファイルのパスの一覧）
- IFileOperation：Windows のファイルのコピー・移動の仕組み。進み具合や「同じ名前があります」の画面を Windows が出してくれる
- ドラッグ＆ドロップ：マウスで押さえたまま動かして、別の場所で離す操作
- OLE：Windows で、アプリ同士がドラッグ＆ドロップやクリップボードでやりとりするための古くからの仕組み
