# タスク 0013 の修正案（2026-10-14T15:40:43、claude_cli:sonnet）

## 理由

tsc の型エラー（TS2339）の原因は、テストファイルが result.message.params を直接読んでいることです。result.message の型 ModToHostMessage は KeyMessage を含む union なので params が無い型が混ざります。実装担当は直したと報告しましたが、ブランチのテストは直っていません。実装（protocol.ts の case "open"）は正しく、テストの書き方だけを直せば足ります。タスクの指示どおり (result.message as CallMessage).params で取り出します。CallMessage は src/api/types.ts に export されています。変更箇所は import 1行と params 参照4箇所で、正確なコードを示せるため direct_fix としました。

## 修正案

work/app/tests/protocol-open-newtab.test.ts を次のように直す。
(1) 2行目の import の後に1行足す:
  import type { CallMessage } from "../src/api/types";
(2) ファイルの先頭に次の小さな関数を足してもよいが、単純にするため各テストで直接キャストする。次の4つのテストで、result.message.params を (result.message as CallMessage).params に置き換える。
  - 15行目: expect((result.message as CallMessage).params).toEqual({ id: "a", path: "C:\\x", newTab: true });
  - 29行目: expect((result.message as CallMessage).params).toEqual({ id: "a", path: "C:\\x", newTab: false });
  - 43行目: expect((result.message as CallMessage).params).toEqual({ id: "a", path: "C:\\x" });
  - 44行目: expect("newTab" in (result.message as CallMessage).params).toBe(false);
  - 63行目: expect((result.message as CallMessage).params).toEqual({
        id: "a",
        path: "C:\\x",
        from: { x: 1, y: 2, width: 3, height: 4 },
        newTab: true,
      });
(3) 最後のテスト（newTab: "yes"）は !result.ok の枝で result.id と result.error.code を読むだけなので、そのまま変えない。
これで tsc --noEmit も通る。もし CallMessage の params が undefined を許す型で 44行目が型エラーになる場合は、44行目を expect(Object.prototype.hasOwnProperty.call((result.message as CallMessage).params, "newTab")).toBe(false); にする。
