# はじめての explorer_plus MOD づくり（初めての人向け・よくある質問つき）

プログラミングやエディタ（IDE）をほとんど使ったことがない人が、AI に手伝ってもらいながら、explorer_plus の自分だけのビュー（MOD）を作って、友だちに配るまでの手引きです。
わからないことが出たら、この資料の「よくある質問」を探してください。

この資料は、MOD 開発ガイド（`guide.md`）の入門編です。ガイドは、API（本体が MOD に用意している機能）を調べるための辞書です。この資料は、最初の1回を止まらずに進むための手引きです。

---

## この資料でいちばん大切な3つのこと

1. **全部を理解しなくて大丈夫です。** コードの意味が分からなくても、AI に頼んで動かすところから始めてよいです。分かりたくなったら、そのとき AI に「この行は何をしているの？」と聞きます。
2. **エラーが出るのは、ふつうのことです。失敗ではありません。** プロの開発者も毎日エラーを見ています。エラーの文は、AI に直してもらうための材料です。
3. **MOD は、壊れても元に戻せます。** 作った MOD は、隔離された箱の中で動きます。パソコンの中身を勝手に消したり、インターネットに送ったりはできません。MOD を外せば、元の explorer_plus に戻ります。

---

## 用語集（言葉が分からなくなったらここ）

- **explorer_plus**：Windows 用のファイラー（ファイルを見て操作するアプリ）。Windows のエクスプローラの代わりに使える。
- **ビュー**：フォルダの中身の「見せ方」。同じフォルダを、一覧、付箋のノート、樹形図など、いろいろな見せ方で見られる。
- **MOD（モッド）**：explorer_plus に足せる、自分で作ったビュー。フォルダ1つに、いくつかのファイルを入れたもの。
- **IDE / エディタ**：プログラムを書くためのアプリ。この資料では VS Code（無料）を例にする。
- **フォルダを開く**：VS Code で、作業するフォルダ全体を開くこと。ファイルを1つだけ開くのとは違う。
- **manifest.json（マニフェスト）**：MOD の名札。名前、版、使う情報などを書いたファイル。
- **index.js**：MOD の本体。ビューの動きを書いた JavaScript（ジャバスクリプト）のファイル。
- **JavaScript**：プログラミング言語のひとつ。MOD はこれで書く。
- **JSON（ジェイソン）**：`{ "名前": "値" }` の形で書く、データの書き方。manifest.json はこの形。カンマや引用符の位置に厳しい。
- **uses（ユージズ）**：manifest.json の中の、「この MOD が使う情報」の一覧。ここに書いていない情報は、MOD に渡されない。
- **API（エーピーアイ）**：explorer_plus が MOD に用意している、頼みごとの窓口。「ファイルを開いて」「名前を変えて」などを本体に頼める。
- **ホットリロード**：ファイルを保存すると、アプリが自動で読み直して、すぐ画面に反映されること。
- **開発中の MOD**：作っている途中の MOD。保存するたびに反映される。
- **ログ**：MOD の動きの記録。エラーが出たときの原因が書いてある。
- **開発者ツール**：アプリの中身をのぞくための画面。エラーの詳しい情報が見られる。
- **コンソール**：開発者ツールの中の、メッセージが流れる欄。
- **zip（ジップ）**：複数のファイルを1つにまとめたファイル。MOD を配るときの形。
- **バイブコーディング**：AI に「こんなものを作って」と日本語で頼み、出てきたコードを動かして確かめながら、感覚（バイブ）で作っていくやり方。
- **プロンプト**：AI への頼みごとの文章。

## 全体の流れ（約30分）

1. explorer_plus を入れる
2. VS Code を入れる
3. 練習用のフォルダを用意する
4. 「ひな形から作る」で、MOD の元を作る
5. VS Code でそのフォルダを開く
6. 動かして、1か所変えてみる（最初の成功）
7. AI に頼んで、作りたいものに変える
8. 友だちに配る（zip）

どこかで詰まったら、「よくある質問」へ。

---

## 1. explorer_plus を入れる

1. GitHub の Releases（<https://github.com/Neptunity-git/explorer_plus/releases>）から、一番新しい版の `explorer_plus_*_x64-setup.exe` をダウンロードして実行する。
2. 「Windows によって PC が保護されました」と出る。これは、まだ配布元の署名（証明）をしていないための表示で、アプリが危険という意味ではない。**「詳細情報」→「実行」** で進める。
3. 入れ終わったら、explorer_plus を起動する。

注意：explorer_plus は **Windows 専用**です。Mac では動きません。

## 2. VS Code を入れる

1. <https://code.visualstudio.com/> から VS Code をダウンロードして入れる。
2. 初めて起動したら、右下に「日本語の言語パックをインストールしますか」と出ることがある。入れると、メニューが日本語になる。
3. これで準備は終わり。拡張機能（追加の部品）は、最初は要らない。

VS Code 以外（Cursor など、AI が入ったエディタ）でも、同じ手順でできる。

## 3. 練習用のフォルダを用意する（大事）

MOD を試すときは、本物の大事なフォルダではなく、**練習用のフォルダ**で試す。

- 理由：AI が書いたコードを試すとき、思いがけずファイルの名前を変えたり、フォルダを作ったりするコードができることがある。練習用なら、失敗しても困らない。
- やり方：デスクトップなどに「練習」というフォルダを作り、写真や適当なファイルを数個コピーして入れる。

## 4. 「ひな形から作る」で、MOD の元を作る

1. explorer_plus で、新しいタブ（`+`）を開くと、ホームが出る。
2. ホームの **「MOD」の欄** にある **「ひな形から作る…」** を押す。
3. 新しい MOD の名前を入れる（日本語でよい。例：「写真マップ」）。**「作る場所を選ぶ」** を押す。
4. MOD のフォルダを作る場所を選ぶ（例：「ドキュメント」の中に「mymods」フォルダを作って選ぶ）。
5. フォルダができ、新しいタブで開く。これが **MOD のフォルダ**。

できるフォルダの中身：

```
写真マップ/
  manifest.json          MOD の名札
  index.js               MOD の本体（ここを書き換えていく）
  style.css              見た目
  explorer-plus.d.ts     VS Code の補完のための定義（触らなくてよい）
  jsconfig.json          VS Code の設定（触らなくてよい）
  MOD開発ガイド.md        説明書（AI に読ませる）
  README.md              簡単な説明
```

## 5. VS Code でそのフォルダを開く

1. VS Code を起動する。
2. メニューの **「ファイル」→「フォルダーを開く」**（英語表示なら File → Open Folder）を選ぶ。
3. 手順4で作った MOD のフォルダを選ぶ。
4. 「このフォルダー内のファイルの作成者を信頼しますか？」と出たら、**「はい、作成者を信頼します」** を押す。自分で作ったフォルダなので大丈夫。
5. 左の一覧に `index.js` などが出る。`index.js` をクリックすると、中身が開く。

**フォルダごと開く**ことが大事。`index.js` だけを開くと、AI や補完が、ほかのファイルを見られない。

## 6. 動かして、1か所変えてみる（最初の成功）

1. explorer_plus のタブで、タブの左の **`▸`** を押す。メニューに、作った MOD の名前が出る。それを選ぶ。
2. 今のフォルダのファイルが、大きい順に並び、大きさが棒で出る。これがひな形のビュー。
3. VS Code に戻り、`index.js` の中の `$title.textContent = ` で始まる行（40行目あたり）を探す。その中の `大きい順` を、好きな言葉（例：`わたしの並び`）に書き換える。ほかの文字や記号（`` ` `` や `${folder.name}`）は消さない。
4. **Ctrl+S（保存）** を押す。
5. explorer_plus に戻ると、見出しが変わっている。これが**ホットリロード**。

ここまでできたら、MOD の作り方の基本は分かったことになる。

## 7. AI に頼んで、作りたいものに変える

### AI の使い方

- AI は、Claude、ChatGPT、GitHub Copilot、Cursor など、何でもよい。
- AI が VS Code の中でフォルダを見られる場合は、`MOD開発ガイド.md` と `index.js` を見てもらう。
- チャットの AI（ブラウザで使うもの）の場合は、`MOD開発ガイド.md` の中身と、今の `index.js`、`manifest.json` を貼り付けてから頼む。

**いちばん大切なコツ：AI に最初に `MOD開発ガイド.md` を読んでもらう。** これを読んでいないと、AI は explorer_plus にない機能を勝手に作って、動かないコードを出しやすい。

### 頼み方の型

```
このフォルダは explorer_plus の MOD です。
MOD開発ガイド.md を読んでから、次のことをしてください。

やりたいこと：ファイルを更新日の新しい順に並べて、今日更新したものを光らせたい
決まり：
- manifest.json の uses も、必要なものだけ書き直す
- 今の index.js を直す形で、ほかのファイルは増やさない
- 変えた場所と、その理由を、短く教えてください
```

ポイント：

- **やりたいことを、1つずつ頼む。** 「全部作って」より、「まず並べ替え」「次に色」と小分けにするほうが、うまくいく。
- **変えた場所の説明を頼む。** あとで「この行は何？」と聞くきっかけになる。
- **動いたら、いったん保存（コピー）しておく。** 次の変更で壊れたとき、戻れる。

### アイデアの例

白紙から考えると時間がかかる。次から選ぶとよい。

| 難しさ | アイデア |
|---|---|
| やさしい | ファイルを種類ごとに色分けして並べる |
| やさしい | 一番大きいファイルを大きく表示する |
| ふつう | 写真を、撮った日で年表のように並べる |
| ふつう | 更新日の新しい順に並べて、今日のものを光らせる |
| ふつう | 課題の締め切りボード（フォルダ名に日付があるものを並べる） |
| チャレンジ | フォルダを部屋に見立てた3D 表示 |

### 動いたかを確かめる流れ

1. AI が出したコードを、`index.js` に貼る（または AI に直接直してもらう）。
2. **Ctrl+S（保存）** を押す。
3. explorer_plus の画面を見る。
4. 変わらない、または何も出ないときは、「よくある質問」へ。

## 8. 友だちに配る（zip）

1. `manifest.json` の `version`（版）を確かめる。ひな形では `0.1.0` になっている。完成したと思ったら、`1.0.0` に変えるとよい。
2. explorer_plus のホームの **「MOD」の欄** で、作った MOD の行にある **「zip にする」** を押す。
3. MOD のフォルダの**隣**に、`id-版.zip`（例：`my.view-xxxx-1.0.0.zip`）ができる。名前が日本語のときは、id は自動で `my.view-` から始まる英数字になる。
4. この zip を友だちに送る（メール、チャット、クラウドなど）。
5. 受け取った人は、ホームの **「＋ MOD を入れる（zip）」** を押して zip を選ぶ。または、ホームのタブに zip をドラッグして落とす。
6. 入れる前に確認の画面が出る。「このビューが使う情報」を見て、よければ入れる。

配る前に、`manifest.json` の `description`（説明）に、何をする MOD かを正直に書く。入れる人は、その説明を信頼して入れる。

## よくある質問

### インストール・環境

**Q. インストーラを開くと「Windows によって PC が保護されました」と出た。ウイルス？**
いいえ。explorer_plus にはまだ「署名」（配布元の証明）がないため、Windows が念のため止めているだけ。「詳細情報」を押すと「実行」のボタンが出るので、それを押す。配布元は GitHub の Releases であることを確かめる。

**Q. Mac や Linux で使える？**
使えない。explorer_plus は Windows 専用。

**Q. 会社や学校のパソコンで、インストールできない。**
管理者がインストールを禁止していることがある。その場合は、自分のパソコンを使うか、管理者に相談する。

**Q. VS Code は必須？**
必須ではない。メモ帳でも MOD は書ける。ただし、VS Code だと補完やエラーの表示があるので、おすすめ。

### VS Code の基本

**Q. 保存したのに、何も変わらない。**
次の順に確かめる。

1. VS Code のタブ（ファイル名の横）に **白い丸（●）** が残っていないか。丸が残っていたら未保存。**Ctrl+S** を押す。
2. 開いているフォルダが、「ひな形から作る」で作った MOD のフォルダか。**コピーや別の場所のフォルダを直していないか**確かめる。
3. explorer_plus で、タブの `▸` から、**作った MOD のビューに切り替えているか**。ほかのビュー（Win11 風など）のままでは、MOD は表示されない。
4. 保存したファイルが `index.js`（または `style.css`、`manifest.json`）か。
5. それでもだめなら、ホームの「ログ」の欄でエラーを見る（下の「エラーが出た」）。

**Q. 毎回 Ctrl+S を押すのが面倒。**
VS Code のメニュー「ファイル」→「自動保存」にチェックを入れると、自動で保存される。

**Q. 「ひな形から作る」で作ったフォルダが見つからない。**
explorer_plus のタブに、MOD のフォルダが開いている。そこで右クリック、または上のアドレスバーを見ると、場所が分かる。ホームの「MOD」の欄で、MOD の行の **「フォルダ」** を押しても開ける。

**Q. VS Code で「信頼しますか」と出た。**
自分で作ったフォルダなら **「はい、作成者を信頼します」** でよい。知らない人から受け取ったフォルダは、中身を確かめてから。

**Q. ファイルを間違えて消した・書き換えた。**
VS Code で **Ctrl+Z** を押すと、直前の変更を取り消せる。前に保存したものを残していないときは、ひな形から作り直す。大事な MOD は、フォルダごとコピーして取っておくとよい（バックアップ）。

### MOD が動かない・エラーが出た

**Q. エラーが出た。どこで見ればいい？**
次の順に見る。

1. explorer_plus のホームの **「ログ」の欄**。作った MOD の名前を選ぶと、その MOD のログが出る。赤い行がエラー。
2. ホームの **「MOD」の欄** で、作った MOD の行に赤い文字が出ていないか。出ていれば、`manifest.json` の書き方の誤り。
3. それでも分からなければ、**「開発者ツール」** ボタンを押す。コンソールに、詳しいエラーが出る。

ログの **「コピー」** ボタンで、ログをまとめてコピーできる。

**Q. エラーの意味が分からない。**
意味が分からなくてよい。エラーの文を**そのまま AI に貼って**、「このエラーを直して」と頼む。次の型が使いやすい。

```
explorer_plus の MOD を作っています。保存したら、次のエラーが出ました。
原因と直し方を、初心者にも分かるように教えてください。

（ここにログのエラーをそのまま貼る）
```

**Q. ホームの「MOD」の欄に赤い文字が出て、MOD が読み込まれない。**
`manifest.json` に誤りがある。よくある原因：

- **最後の項目の後ろに、余計なカンマ `,` がある**（JSON ではだめ）。
- **引用符が全角（“ ”）になっている。** JSON では半角の `"` だけ使える。日本語入力がオンのまま打つと、全角になる。
- **スペースが全角（　）になっている。**
- **JSON の中にコメント（`//` や `/* */`）を書いた。** JSON ではコメントは書けない。
- **`apiVersion` が 1 でない。**

赤い文字の説明を、そのまま AI に貼ると、直してもらえる。

**Q. `not-declared` というエラーが出た。**
`manifest.json` の `uses` に、必要な項目を書いていないという意味。たとえば、次のように足す。

| やりたいこと | uses に足すもの |
|---|---|
| ファイルの名前・種類を見る | `entries` |
| ファイルの大きさを見る | `size` |
| 更新日時を見る | `modified` |
| アイコンを出す | `icons` |
| 画像の縮小画像（サムネイル）を出す | `thumbnails` |
| ファイルの中身（文字）を読む | `fileContent` |
| 写真の撮影日などを見る | `fileInfo` |

`uses` を直して保存すれば、反映される。AI に「`not-declared` が出た。uses に何を足せばいい？」と聞いてもよい。

**Q. 画面が真っ白になった。**
JavaScript のどこかでエラーが出て、止まっている可能性が高い。ログを見て、エラーを AI に貼る。AI に「直前の変更を元に戻して」と頼むのもよい。

**Q. AI が出したコードが動かない。「~ is not a function」などと出る。**
AI が、explorer_plus にない機能（存在しない関数）を作ってしまった可能性が高い。次のように頼む。

```
その関数は explorer_plus にありません。
MOD開発ガイド.md に書かれている API だけを使って、書き直してください。
```

**Q. 一度動いたのに、次の変更で動かなくなった。**
AI に「直前の変更を元に戻して」と頼む。または、バックアップ（手順7で取っておいたコピー）に戻す。小分けにして頼み、動くたびにコピーを取っておくと、戻りやすい。

**Q. 自分の MOD が、タブの `▸` のメニューに出ない。**
ホームの「MOD」の欄に、MOD が入っているかを確かめる。入っていなければ、**「開発中のフォルダを読み込む…」** を押して、MOD のフォルダ（`manifest.json` があるフォルダ）を選ぶ。

### 作りたいものを AI に伝えるとき

**Q. AI にどう頼めばいいか分からない。**
次の3つを書くと伝わりやすい。

1. **何を見せたいか**（例：「ファイルを更新日順に」）
2. **見た目のイメージ**（例：「暗い背景に、緑の文字で」）
3. **決まり**（例：「MOD開発ガイド.md の API だけを使う」「ほかのファイルは増やさない」）

**Q. AI が、ファイルをたくさん作ろうとする。**
「index.js 1つだけで作って」「ほかのファイルは増やさない」と頼む。最初は、ファイルが少ないほうが分かりやすい。

**Q. AI が、インターネットから何かを読み込むコードを書いた。**
MOD は、デフォルトでは外部と通信できない（自分のフォルダの中のものだけ）。通信が必要な場合は、`manifest.json` の `network` に書いた先だけ使える。初心者は、まず通信なしで作ることをおすすめする。AI に「インターネットを使わない形で書き直して」と頼む。

**Q. AI が書いたコードが何をしているか、分からない。**
「このコードの、この部分は何をしていますか？初心者にも分かるように説明して」と聞く。分からないままでも動くが、聞くことで理解が進む。

### 安全について

**Q. 作った MOD で、パソコンのファイルが消えたりしない？**
MOD は、隔離された箱の中で動く。ファイルを消す機能（ごみ箱へ送る）は、本体が**確認の画面**を出すので、勝手には消えない。ただし、ファイルの名前の変更や、フォルダの新規作成などは、確認なしでできる機能がある。そのため、**最初は練習用のフォルダで試す**ことをおすすめする。

**Q. 友だちの作った MOD を入れても大丈夫？**
入れる前に、確認の画面で「このビューが使う情報」が見える。使う情報が多すぎないか、説明に合っているかを見て、よければ入れる。知らない人の MOD は、慎重に。

**Q. 入れた MOD を外したい。**
ホームの「MOD」の欄で、その MOD の行の **「外す」** を押す（開発中の MOD は **「読み込みをやめる」**）。外しても、フォルダの中身は消えない。

### 配るとき

**Q. 「zip にする」を押したのに、zip が見つからない。**
zip は、**MOD のフォルダの隣**（同じ階層）にできる。MOD のフォルダの1つ上のフォルダを見る。ファイル名は `id-版.zip`（例：`my.view-xxxx-1.0.0.zip`）。

**Q. 友だちが zip を入れようとしたら、うまくいかない。**
- 友だちが、Windows で explorer_plus を入れているか。
- zip を**解凍せずに**、そのまま「MOD を入れる」で選んでいるか。
- zip の中の `manifest.json` が、最上位、または1つだけのフォルダの中にあるか。

**Q. 版（version）はどう決める？**
ひな形では `0.1.0`。完成したら `1.0.0` にしてよい。直して配り直すときは、`1.0.1`、`1.1.0` のように、数字を大きくする。同じ id で、版を上げた zip を入れると、「更新」になる。

**Q. id を変えたほうがいい？**
自分の MOD が、ほかの人の MOD と重ならないように、`自分の名前.ビューの名前` の形（例：`taro.photo-map`）をおすすめする。id は、半角英小文字・数字・`.`・`-` だけ使える。

## 困ったときの順番

1. **保存したか確かめる**（Ctrl+S）。
2. **正しいフォルダ・正しいビューか確かめる**（タブの `▸`）。
3. **ホームの「ログ」の欄を見る。** 赤い行がエラー。
4. **エラーをそのまま AI に貼って、直してもらう。**
5. それでも直らなければ、**直前の動いていた状態に戻す**（Ctrl+Z、または AI に「元に戻して」）。
6. 周りの人に聞く。そのとき、**ログのコピー**と**やったこと**を見せると、早く答えてもらえる。

## 次の一歩

最初の MOD ができたら、次のことに進める。

- **もう少し変えてみる**：色、並び順、表示する情報を変えてみる。AI に「次は〇〇を足したい」と頼む。
- **コードを読んでみる**：`index.js` を上から読んで、AI に「ここは何をしている？」と聞く。
- **ガイドを読んでみる**：`MOD開発ガイド.md` の「API」の章を、気になるところから読む。
- **見せ合う**：作った MOD の zip を友だちと交換して、入れ合う。人に使ってもらうと、直したい点が見つかる。
- **GitHub で公開する**：作った MOD を GitHub に置くと、バックアップになり、ほかの人にも使ってもらえる。みんなの MOD の一覧（<https://github.com/Neptunity-git/explorer_plus-mods>）にも載せられる。git のコマンドもインストールも要らず、ブラウザだけでできる。手順は `share.md`（作った MOD を公開して共有する）にある。これが、バージョン管理（git）の入口になる。
- **本体の開発に参加する**：explorer_plus は公開されている。<https://github.com/Neptunity-git/explorer_plus> の `CONTRIBUTING.md` に参加の仕方がある。
