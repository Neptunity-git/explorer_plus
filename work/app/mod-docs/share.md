# 作った MOD を公開して共有する（GitHub が初めての人向け）

自分で作った explorer_plus の MOD を、GitHub で公開して、友だちや世界中の人に使ってもらうまでの手引きです。

**git のコマンドも、git のインストールも要りません。ブラウザだけでできます。** 画面に出る言葉を、そのまま書いてあります。

この資料の前に、`beginner.md`（はじめての MOD づくり）で、最初の MOD ができていることを前提にしています。

---

## 先に知っておく3つのこと

1. **公開すると、誰でも見られます。** 名前（ユーザー名）やコードが、インターネットに出ます。ここだけは、慎重に進めてください。「公開前に確かめること」の章を、必ず読んでから公開します。
2. **失敗しても大丈夫です。** GitHub は、ファイルの変更を全部記録します。間違えても、直せます。消すこともできます。
3. **全部を覚えなくて大丈夫です。** 最初は、手順どおりに進めるだけでよいです。分からない言葉は、すぐ下の用語集で調べます。

---

## 用語集

- **git（ギット）**：ファイルの変更の履歴を、記録しておく仕組み。「いつ、何を、どう変えたか」が残るので、前の状態に戻れる。
- **GitHub（ギットハブ）**：git で記録したものを、インターネットに置いて、共有するサービス（無料で使える）。
- **アカウント**：GitHub を使うための自分の登録。ユーザー名とパスワードがある。
- **ユーザー名**：GitHub 上の自分の名前。公開される。後から変えられるが、変えるとリンクが変わる。
- **リポジトリ（repository）**：ファイルを置く箱。MOD 1つにつき、1つ作る。
- **Public / Private**：リポジトリを、誰でも見られる（Public）か、自分だけが見られる（Private）か。MOD を配るなら Public。
- **コミット（commit）**：ファイルの変更を、記録すること。「Commit changes」というボタンで押す。
- **Releases（リリース）**：リポジトリに、「完成した版」を zip などで付けて、配るための場所。
- **タグ（tag）**：版の名前。`v1.0.0` のように付ける。
- **フォーク（fork）**：他の人のリポジトリを、自分のところにコピーすること。変更を提案するときに使う。
- **プルリクエスト（pull request）**：「ここをこう変えたので、取り込んでください」という、変更の提案。
- **メンテナー**：リポジトリの管理をしている人。プルリクエストを見て、取り込むか決める。
- **ライセンス**：他の人が、作品を使ってよい範囲を決めた文書。
- **一覧（explorer_plus-mods）**：みんなの MOD を載せた一覧のリポジトリ。ここに載せると、探している人に見つけてもらいやすくなる。

---

## 全体の流れ（約40分）

1. 公開前に確かめる（5分）
2. GitHub のアカウントを作る（10分。すでにあれば飛ばす）
3. リポジトリを作る
4. MOD のファイルを置く
5. zip を Releases に付けて、公開する
6. 友だちが入れられるか確かめる
7. 一覧に載せる（任意）

---

## 1. 公開前に確かめること

公開する前に、次を必ず見ます。

- **パスワードや API キーが、ファイルの中に書かれていない。** `index.js` や `manifest.json` を開いて、`sk-`、`key`、`password`、`token` などの文字を探す。AI に「秘密の情報が入っていないか確かめて」と頼んでもよい。API キーは、設定の `secret` で預ける決まりです（`guide.md` の「API キー」）。
- **自分や他の人の写真・個人情報が入っていない。** 試すために入れた写真、名前、住所、学校名などがないか確かめる。
- **他の人が作ったものを、勝手に入れていない。** 画像、文章、ライブラリは、使ってよいものだけにする。
- **`manifest.json` の `description`（説明）に、何をする MOD かが、正直に書いてある。**
- **`uses`（使う情報）が、必要なものだけになっている。**

迷ったら、公開しないで、先に周りの人か AI に相談します。

---

## 2. GitHub のアカウントを作る

1. ブラウザで <https://github.com/> を開く。
2. 右上の **「Sign up」** を押す。
3. メールアドレス、パスワード、**ユーザー名**を入れる。
   - **ユーザー名は公開されます。** 本名を出したくない人は、別の名前にする。
   - ユーザー名は半角の英数字とハイフンだけ。
4. 画面の指示に従って、確認のパズルを解き、メールに届いた確認の番号を入れる。
5. 作り終わったら、右上のアイコン →「Settings」→「Emails」を開き、**「Keep my email addresses private」（メールアドレスを隠す）** にチェックを入れる。
   - 理由：何もしないと、変更を記録するときに、自分のメールアドレスが公開されてしまうことがある。
6. できれば、「Settings」→「Password and authentication」から、**二段階認証**（パスワードのほかに、スマホで確認する仕組み）も設定する。アカウントを守れる。

注意：GitHub は、**13歳以上**の人が使える決まりです。

画面は英語が基本です。ボタンの名前が、この資料と少し違っていたら、似た名前のボタンを探してください。

---

## 3. リポジトリを作る

1. GitHub の画面の右上にある **「＋」** を押し、**「New repository」** を選ぶ。
2. 次のように入れる。
   - **Repository name**：MOD の名前（半角の英数字とハイフン。例：`photo-map`）。日本語や空白は使えない。
   - **Description**：何をする MOD か、短く（任意）。
   - **Public** を選ぶ。**Private にすると、他の人がダウンロードできません。**
   - **「Add a README file」** にチェックを入れる。
   - 「Add .gitignore」と「Choose a license」は、ここでは触らなくてよい（ライセンスは後で足せる）。
3. **「Create repository」** を押す。

これで、自分のリポジトリができました。URL は `https://github.com/あなたのユーザー名/photo-map` の形です。

---

## 4. MOD のファイルを置く

1. 作ったリポジトリのページで、**「Add file」** →**「Upload files」** を選ぶ。
2. explorer_plus で作った MOD のフォルダを開き、**中のファイル**を、ブラウザの枠にドラッグして落とす。
   - 落とすのは、`manifest.json`、`index.js`、`style.css`、画像など、MOD が使うファイル。
   - **フォルダごと**落とすのではなく、**中身**を落とします。そうしないと、`manifest.json` が一番上に来ません。
   - `explorer-plus.d.ts`、`jsconfig.json`、`MOD開発ガイド.md` は、作るときだけ使うファイルなので、置かなくてもよい。
   - `node_modules` というフォルダがあれば、落とさない。
3. 下の **「Commit changes」** を押す。上の欄には、「MOD のファイルを置く」のように、何をしたかを書くとよい（書かなくても押せる）。

置いたファイルが、リポジトリのページに並べば成功です。

---

## 5. zip を Releases に付けて、公開する

友だちが入れる zip は、「Releases」という場所に付けます。

### zip を作る

1. explorer_plus のホームの **「MOD」の欄** で、作った MOD の行にある **「zip にする」** を押す。
2. MOD のフォルダの**隣**に、`id-版.zip`（例：`taro.photo-map-1.0.0.zip`）ができる。
3. その前に、`manifest.json` の `version`（版）を確かめる。公開するなら、`1.0.0` にするのがおすすめ。変えたら、手順4と同じ方法で、リポジトリの `manifest.json` も入れ替えておく。

### Release を作る

1. 自分のリポジトリのページを開く。
2. 右側にある **「Releases」** の **「Create a new release」** を押す。
3. **「Choose a tag」** を押し、版の名前を入れる。`manifest.json` の `version` の前に `v` を付ける（例：`v1.0.0`）。すると **「Create new tag: v1.0.0 on publish」** と出るので、それを選ぶ。
4. **「Release title」** に、`1.0.0` や `最初の版` など、分かりやすい名前を入れる。
5. 説明の欄に、MOD の説明を簡単に書く（何をするか、変わったこと）。
6. 下の **「Attach binaries by dropping them here or selecting them.」** の枠に、手順「zip を作る」でできた **zip をドラッグして落とす**。**アップロードが終わる（バーが消える）まで待つ。**
7. **「Publish release」** を押す。

Release のページに、zip が並べば成功です。

---

## 6. 友だちが入れられるか確かめる

1. ブラウザの**プライベートウィンドウ**（ログインしていない状態）で、`https://github.com/あなたのユーザー名/photo-map/releases` を開く。
2. zip が見えて、ダウンロードできれば、友だちも入れられます。
3. ダウンロードした zip を、explorer_plus のホームの **「＋ MOD を入れる（zip）」** で入れてみる。確認の画面が出れば成功です。

見えないときは、リポジトリが **Public** か確かめます（リポジトリの「Settings」→一番下の「Danger Zone」に、公開・非公開を変える項目があります）。

---

## 7. 一覧に載せる（任意）

作った MOD を、みんなが探せる一覧（`explorer_plus-mods`）に載せられます。

載せ方は、一覧のリポジトリの README にあります。
<https://github.com/Neptunity-git/explorer_plus-mods>

流れだけ書くと、次のとおりです。

1. 一覧のリポジトリの `mods.json` を開き、**鉛筆のマーク**を押す。
2. 自分の MOD の情報（`id`、`name`、`description`、`author`、`repo`）を1件足す。
3. **「Commit changes...」** → **「Propose changes」** → **「Create pull request」** を押す。
4. 自動の確認が通れば、メンテナーが見て、取り込む。

これが、**プルリクエスト**です。GitHub で、他の人と一緒に何かを作るときの基本の動きを、一度経験できます。

---

## 更新するとき

MOD を直して、新しい版を配りたいときです。

1. MOD のファイルを直す。
2. `manifest.json` の `version` を上げる（例：`1.0.0` → `1.0.1`）。
3. 手順4と同じ方法で、リポジトリのファイルを入れ替える。同じ名前のファイルを落とすと、置き換わる。
4. 「zip にする」で、新しい zip を作る。
5. 手順5と同じ方法で、新しい Release を作る（タグは `v1.0.1`）。

一覧への書き直しは、**要りません**（場所だけが書いてあるため）。

## よくある質問

### 公開・安全について

**Q. 公開したら、取り消せる？**
リポジトリや Release は、あとで消せたり、Private に戻したりできます。ただし、公開している間に、誰かがコピーしていることがあります。**消しても、完全には取り消せない**と考えて、公開前によく確かめてください。

**Q. API キーやパスワードを、間違えて公開してしまった。**
すぐに、そのキーやパスワードを**無効にして、新しく作り直して**ください（サービスの設定画面から）。リポジトリを消すだけでは足りません。すでに誰かに見られている可能性があるためです。

**Q. 自分の本名やメールアドレスが、出てしまわないか心配。**
- ユーザー名は、本名でなくてよい。
- アカウント作成の手順5の設定（「Keep my email addresses private」）をしておく。
- コードやファイルの中に、本名、学校名、住所などを書かない。

**Q. 友だちの顔が写った写真を、サンプルに入れてもいい？**
入れないでください。写っている人の許可があっても、公開すると取り消しにくいためです。サンプルには、自分で撮った風景や、使ってよい素材を使います。

**Q. ライセンスって何？どれを選べばいい？**
他の人に「どこまで使ってよいか」を伝える文書です。迷ったら **MIT** がおすすめです（自由に使ってよいが、責任は取らない、という内容の短いもの）。リポジトリのページで、「Add file」→「Create new file」を選び、ファイル名に `LICENSE` と入れると、「Choose a license template」というボタンが出ます。それを押して MIT を選びます。

### 作業でつまずいたとき

**Q. 「Upload files」で、ファイルが落とせない。**
ブラウザの枠にドラッグするか、「choose your files」というリンクを押して、ファイルを選びます。フォルダごとだと、うまくいかないことがあります。その場合は、中のファイルを選び直します。

**Q. リポジトリに、フォルダが1つ増えて、`manifest.json` がその中に入ってしまった。**
フォルダごと落としたためです。一度そのフォルダを開き、ファイルを選んで削除し、**中身だけ**を落とし直します。または、一覧に載せるときに `path` にそのフォルダの名前を書きます（例：`"path": "photo-map"`）。

**Q. Release に zip が付かなかった。**
アップロードが終わる前に「Publish release」を押した可能性があります。Release のページで、鉛筆のマーク（Edit）を押し、zip を落とし直して、「Update release」を押します。

**Q. 「Source code (zip)」というのが出ているが、これは何？**
GitHub が自動で付ける、リポジトリ全体の zip です。explorer_plus は、これも入れられますが、自分で付けた zip（「zip にする」で作ったもの）のほうが、必要なファイルだけで整っています。友だちには、自分で付けた zip を案内してください。

**Q. 友だちが入れようとしたら、うまくいかない。**
- zip を**解凍せずに**、そのまま「MOD を入れる」で選んでいるか。
- 友だちが、Windows で explorer_plus を使っているか。
- zip の中の `manifest.json` が、`id` と `version` を持っているか。

**Q. 間違えたファイルを置いてしまった。消したい。**
リポジトリのページでそのファイルを開き、右上の **「…」** メニューから **「Delete file」** を選んで、「Commit changes」を押します。

**Q. 一覧のプルリクエストで、✗ が出た。**
「Details」を押すと、直すところが日本語で出ます（例：「`id` は半角の英小文字・数字だけにしてください」）。同じプルリクエストの画面から、ファイルを直せます。直したら、自動でもう一度確認されます。

**Q. 一覧のプルリクエストが、いつまでたっても取り込まれない。**
メンテナーが、見ていないだけかもしれません。数日待っても動かなければ、プルリクエストにコメントを書いてみてください。

### その他

**Q. 一覧に載せなくても、友だちに配れる？**
配れます。zip を送るか、リポジトリの Releases のURLを教えればよいです。一覧は、知らない人にも見つけてもらいたいときの近道です。

**Q. 一覧に載せたあと、外したい。**
`mods.json` から自分の項目を消す、プルリクエストを出します。

## 次の段階：git を入れて、使ってみる

ここまでは、ブラウザだけで進めました。MOD を何度も直して、公開していくうちに、「ファイルを毎回ドラッグするのが面倒」と感じたら、git を入れる頃です。

### 方法A：GitHub Desktop（ボタンで操作する。初めての人におすすめ）

1. <https://desktop.github.com/> から GitHub Desktop を入れる。
2. 起動して、GitHub のアカウントでサインインする。
3. 自分のリポジトリを選んで **「Clone」**（自分のパソコンにコピーする）する。
4. コピーされたフォルダの中で、MOD のファイルを直す。
5. GitHub Desktop に戻ると、変えたところが出る。下の欄に、何をしたかを書いて **「Commit to main」**（記録する）を押す。
6. 右上の **「Push origin」**（GitHub に送る）を押す。

### 方法B：VS Code の「ソース管理」

1. <https://git-scm.com/> から git を入れる（設定は、最初は全部そのままでよい）。
2. VS Code で MOD のフォルダを開き、左の **「ソース管理」**（枝分かれのマーク）を押す。
3. 「リポジトリを初期化する」か、GitHub のリポジトリを「クローン」する。
4. 変えたファイルの横の「＋」を押し、メッセージを書いて「コミット」、そして「同期」を押す。

### 新しく出てくる言葉

- **クローン（clone）**：GitHub のリポジトリを、自分のパソコンにコピーすること。
- **コミット（commit）**：変更を、自分のパソコンの中に記録すること。
- **プッシュ（push）**：記録した変更を、GitHub に送ること。
- **プル（pull）**：GitHub の最新の状態を、自分のパソコンに取り込むこと。
- **ブランチ（branch）**：作業の枝分かれ。最初は「main」だけでよい。

### コマンドで操作したくなったら

`git clone`、`git add`、`git commit`、`git push` が、基本の4つです。AI に「GitHub Desktop の操作を、git のコマンドで言うとどうなるか教えて」と聞くと、対応を教えてもらえます。

## 困ったときの順番

1. **画面の言葉を、この資料と見比べる。** 似た名前のボタンがないか探す。
2. **エラーの文章や、画面の様子を、そのまま AI に伝える。** 「GitHub で〇〇をしようとして、こう出た」と書く。
3. **間違えたファイルは、消して置き直す。** GitHub は、やり直せる。
4. **公開前の確認（1章）に戻る。** 秘密の情報が入っていないか。
5. 周りの人に聞く。そのとき、**画面のスクリーンショット**を見せると、早く答えてもらえる。

## 次の一歩

- **他の人の MOD を入れてみる。** 一覧（<https://github.com/Neptunity-git/explorer_plus-mods>）から、気になる MOD を探して、入れる。
- **他の人の MOD に、感想や提案を送る。** リポジトリの「Issues」で、書ける。
- **自分の MOD を育てる。** 使ってくれた人の声をもとに、直して、新しい版を出す。
- **explorer_plus 本体に参加する。** <https://github.com/Neptunity-git/explorer_plus> の `CONTRIBUTING.md` に、参加の仕方がある。
